# 행사 큐시트 프로그램

이 저장소는 행사 대본과 진행 순서를 작성하고, 휴대전화·태블릿·PC에서 큐시트를 보며 행사를 진행하기 위한 웹앱입니다.

- 운영 사이트: https://quesheet-khc.netlify.app
- 기본 브랜치: `main`
- 배포 서비스: Netlify

## 사이트의 목적

행사별 큐시트와 사회자 대본을 한곳에서 작성하고 관리합니다. 행사 중에는 진행 화면에서 순서를 한 장씩 넘기며 대본, 준비물, 돌발상황 대응 내용을 확인할 수 있습니다. 앱을 한 번 정상적으로 연 뒤에는 오프라인에서도 사용할 수 있도록 만들어져 있습니다.

## 현재 주요 기능

- 행사 생성, 수정, 복제, 삭제
- 행사 순서 추가, 수정, 삭제, 이동 및 사용 여부 설정
- 기본 행사 양식으로 큐시트 만들기
- 전체 대본 보기와 인쇄
- 모바일 행사 진행 화면
- 좌우 밀기와 PC 키보드 방향키로 순서 이동
- 진행 완료 표시와 경과 시간 확인
- 진행 화면 글자 크기 변경
- 지원 브라우저에서 화면 꺼짐 방지
- 진동 알림
- JSON 파일로 전체 또는 개별 행사 백업
- JSON 백업 파일 불러오기
- 홈 화면 설치와 오프라인 실행

## 파일과 폴더의 역할

| 경로 | 역할 |
| --- | --- |
| `index.html` | 사이트가 처음 열릴 때 사용하는 기본 HTML 문서입니다. |
| `assets/app-v1.5.css` | 화면 색상, 크기, 모바일·PC 배치와 인쇄 모양을 담당합니다. |
| `assets/app-v1.5.js` | 행사 편집, 저장, 백업, 진행 화면 등 핵심 기능을 담당합니다. |
| `manifest.webmanifest` | 휴대전화 홈 화면 설치에 필요한 앱 이름, 색상, 아이콘을 설정합니다. |
| `sw.js` | 필요한 파일을 브라우저에 저장하여 오프라인 사용을 지원합니다. |
| `reset.html` | 이전 서비스 워커와 오프라인 캐시를 정리하는 복구 화면입니다. 행사 데이터는 지우지 않습니다. |
| `scripts/build.mjs` | 배포할 파일을 `dist` 폴더에 모으고 공유 주소를 준비합니다. |
| `netlify.toml` | Netlify의 빌드 명령과 배포 폴더를 지정합니다. |
| `_headers` | 보안 헤더와 브라우저 캐시 정책을 설정합니다. |
| `_redirects` | 사이트 내부 주소를 기본 화면으로 연결합니다. |
| `icon-192.png`, `icon-512.png` | 홈 화면 설치용 앱 아이콘입니다. |
| `og-thumbnail-v1.5.jpg` | 카카오톡과 SNS 등에 링크를 공유할 때 사용하는 대표 이미지입니다. |
| `package.json` | 프로젝트 이름, 버전과 `npm run build` 명령을 정의합니다. |
| `TEST-CHECKLIST.md` | 배포 전후에 사람이 직접 확인할 테스트 목록입니다. |

## Netlify 자동배포 구조

Netlify는 GitHub 저장소의 `main` 브랜치와 연결되어 있습니다.

1. 검토가 끝난 변경사항을 `main` 브랜치에 합칩니다.
2. Netlify가 변경을 자동으로 감지합니다.
3. `netlify.toml`에 따라 `node scripts/build.mjs`를 실행합니다.
4. 빌드 프로그램이 `dist` 폴더를 새로 만듭니다.
5. Netlify가 `dist` 폴더를 운영 사이트에 배포합니다.

작업 브랜치에 저장한 내용은 `main`에 합치기 전까지 운영 사이트에 반영되지 않습니다. 작업할 때는 `main`에서 직접 수정하지 말고 별도의 작업 브랜치를 사용합니다.

## 로컬에서 빌드하는 방법

Node.js와 npm이 설치된 컴퓨터에서 저장소 폴더를 연 뒤 다음 명령을 실행합니다.

```bash
npm run build
```

정상적으로 끝나면 저장소 안에 `dist` 폴더가 만들어집니다. `dist/index.html`, `dist/assets`, 아이콘, 서비스 워커 등의 배포 파일이 있는지 확인합니다.

로컬 빌드에서는 Netlify의 사이트 주소 환경변수가 없다는 안내가 나올 수 있습니다. 빌드가 오류 없이 끝나고 `dist`가 생성됐다면 정상입니다. 실제 Netlify 배포에서는 Netlify가 사이트 주소 환경변수를 제공합니다.

## 큐시트 JSON 백업 방법

중요한 행사를 작성한 뒤에는 반드시 JSON 백업 파일을 별도로 보관합니다.

1. 사이트 첫 화면에서 백업 또는 내보내기 기능을 선택합니다.
2. 전체 행사 또는 필요한 개별 행사를 내보냅니다.
3. 내려받은 `.json` 파일을 찾기 쉬운 폴더에 보관합니다.
4. 행사명과 백업 날짜를 파일명 또는 보관 폴더에 표시합니다.
5. 중요한 행사는 PC와 별도 저장장치 등 두 곳 이상에 보관하는 것을 권장합니다.

## 큐시트 JSON 복원 방법

1. 사이트에서 백업 불러오기 기능을 선택합니다.
2. 이전에 내려받은 `.json` 파일을 선택합니다.
3. 불러온 행사가 목록에 추가됐는지 확인합니다.
4. 행사 제목, 순서, 대본 내용이 맞는지 확인합니다.
5. 복원 확인 전에는 기존 백업 파일을 삭제하지 않습니다.

불러오기는 올바른 큐시트 JSON 파일만 사용해야 합니다. 출처를 알 수 없거나 내용을 신뢰할 수 없는 파일은 불러오지 않습니다.

## 브라우저 데이터를 삭제할 때 주의사항

큐시트 내용은 서버 계정이 아니라 현재 기기의 브라우저 `localStorage`에 저장됩니다. 다음 작업을 하면 저장한 행사가 사라질 수 있습니다.

- 브라우저의 사이트 데이터 또는 쿠키와 저장공간 삭제
- 시크릿·비공개 모드 사용 후 창 닫기
- 브라우저 앱 삭제 또는 초기화
- 휴대전화나 PC 교체
- 운영체제 또는 관리 프로그램의 저장공간 정리

브라우저 데이터를 삭제하기 전에는 반드시 JSON 백업을 내려받고, 다른 위치에 파일이 실제로 저장됐는지 확인합니다. 캐시만 정리하는 `reset.html` 또는 `?reset=1` 기능은 행사 데이터 삭제를 목적으로 하지 않지만, 중요한 작업 전에는 항상 백업을 먼저 권장합니다.

## 오류가 생겼을 때 기본 복구 방법

아래 순서대로 하나씩 확인합니다.

1. 먼저 JSON 백업 파일이 있는지 확인합니다.
2. 사이트를 완전히 닫았다가 다시 엽니다.
3. 인터넷 연결 상태에서 운영 사이트를 새로고침합니다.
4. 최신 화면이 계속 나오지 않으면 `/reset.html`을 엽니다.
5. 자동으로 첫 화면으로 돌아오면 기능을 다시 확인합니다.
6. 다른 브라우저 또는 다른 기기에서도 같은 오류가 발생하는지 확인합니다.
7. GitHub의 최근 변경사항과 Netlify 배포 성공 여부를 확인합니다.
8. 오류 화면, 발생한 동작, 사용 기기와 브라우저를 기록합니다.

브라우저 데이터를 직접 삭제해야 한다면 반드시 JSON 백업을 먼저 확보합니다. 복구가 되지 않으면 정상 작동했던 이전 GitHub 버전과 비교하되, 원인을 확인하기 전에 `main` 브랜치를 임의로 되돌리지 않습니다.

## 코드를 수정할 때 지켜야 할 원칙

1. `main` 브랜치에서 직접 작업하지 않고 목적별 작업 브랜치를 만듭니다.
2. 한 작업에서는 관련된 파일만 수정합니다.
3. `index.html`, CSS, JavaScript 또는 서비스 워커를 수정했다면 `npm run build`를 실행합니다.
4. 빌드 성공과 `dist` 폴더 생성을 확인합니다.
5. `TEST-CHECKLIST.md`에서 변경과 관련된 항목을 시험합니다.
6. 모바일과 PC에서 모두 확인합니다.
7. 기존 브라우저 데이터와 JSON 백업이 계속 작동하는지 확인합니다.
8. API 키, 비밀번호, 개인정보를 코드와 GitHub에 넣지 않습니다.
9. 필요한 비밀값은 Netlify 환경변수 등 별도의 안전한 설정에 저장합니다.
10. 외부 라이브러리를 추가하기 전에 꼭 필요한지와 보안·유지관리 영향을 확인합니다.
11. 파일명이나 서비스 워커 캐시 버전을 변경할 때 관련 경로를 모두 함께 점검합니다.
12. 검토와 테스트가 끝나기 전에는 작업 브랜치를 `main`에 합치지 않습니다.

## 배포 전 확인

변경 작업을 마친 뒤에는 [TEST-CHECKLIST.md](./TEST-CHECKLIST.md)를 사용해 주요 기능을 확인합니다. 특히 행사 전에는 JSON 백업, 오프라인 실행, 화면 꺼짐 방지와 실제 진행 기기의 브라우저 동작을 다시 확인합니다.
